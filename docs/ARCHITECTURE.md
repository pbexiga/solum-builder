# Architecture

## Data flow
```
circuit.json ─► load/validate ─► connectivity (nets) ─► netlist ─► SimEngine (native)
                                                                     │
                     rules (topology) ◄── nets                       ▼
                     rules (operating point) ◄──────────────── raw results ─► analysis (gain, harmonics, measures)
                                                                     │
                                                    cache (hash → results) ─► API ─► web UI panels
```

## Where browser code goes (D-284)

`web/app.js` is the app root: the one `state` object, and what acts on the open circuit
as a whole (open and show, edit and undo, select, run and render). It was 3,100 lines;
it stays the root only. **New browser code does not go in `app.js` unless it is one of
those jobs.** Put it here:

| What you are adding | Where |
|---|---|
| A File dialog (another Save…), anything about the saved file or its name | `web/file-dialogs.js` |
| A Blocks dialog, something about saving or managing blocks | `web/block-dialogs.js` |
| A menu item, a new menu, a right-click entry | `web/app-menus.js` (the list); the command itself where it belongs, passed in as a callback |
| A palette tile or tool | `web/palette.js` (a new part type's tile comes from `PALETTE` in `editor/edit.js`, no code here) |
| Power: the supply menu, chip, current drawn, Custom… | `web/power.js` |
| A field or behaviour of a part's form | the field itself in `web/editor/fields.js` (no DOM); the form around it in `web/inspector.js` |
| Slider behaviour (drag, release, cancel) | `web/live-sliders.js`; the slider control is `web/editor/slider.js`, the steps and solve `web/live.js` |
| A result pane | a module of its own beside `stages.js`, `notes.js`, `audio.js` (a `…-logic.js` twin for what needs no DOM), built in the root |
| A Tools or Help page | `web/tools.js`, `web/help.js` |
| An edit to the circuit JSON | a pure function in `web/editor/edit.js` (or `blocks.js`, `insert.js`); the root only applies it |
| A generic form helper (a button row, a question) | `web/editor/form.js` |
| Anything remembered between visits (in the browser, or a preference the server keeps, D-311) | through `web/storage.js` |

**The pattern** (the panes have always used it): a module exports one factory,
`thing(host, app)`, called once in the root. `host` is the element it draws in or opens
its forms on. `app` is a plain object of callbacks, typed in the module as a JSDoc
typedef (`FileApp`, `BlockApp`, `MenuApp`, `PaletteApp`, `PowerApp`, `InspectorApp`,
`SliderApp`): getters for what it reads (`circuit: () => state.circuit`) and one function
per thing it asks the root to do (`tryEdit`, `go`, `showError`, `hint`). The factory
returns the few functions the root and other modules call.

Rules that keep it working:
- A module never imports `app.js` (types only, `import("./app.js").Source`) and never
  sees `state`: it reads through its getters, so the shape of `state` can change (tabs
  will gather what belongs to one open circuit into one object) without touching it.
- A module needs something new from the root: add one callback to its typedef and to the
  object the root passes. Don't reach for the DOM of another module instead.
- In the root, pass `() => fn()` rather than `fn` for anything declared with `const`
  further down the file (it isn't defined yet when the modules are built).
- State only one module uses lives in that module (the ports being marked in
  `block-dialogs.js`, the part whose form is open in `inspector.js`), not in `state`.
- One module may be handed another's returned object (`app-menus.js` gets `files` and
  `blocks`); modules don't build each other.
- `make jslint` (in `make lint`, `make check` and the pre-commit hook, D-286) catches a
  name that is never declared or imported, an unused import and an import the other
  module doesn't export, so moved code fails there, not when its line runs. It does not
  check types or property names (`app.tryEdti` passes): the UI tests (`make accept`)
  cover what the modules do. A browser API used for the first time is added to
  `GLOBALS` in `scripts/jscheck.js`.

## Simulation notes (see D-027, D-028, D-029)
- One analysis of each kind per netlist; read results with `SimResult.plot("op" | "ac" | "tran")`.
- Long transients: keep only what is measured (`Tran.keep_from`; a tone's run records every node but only its last cycles, D-277), since ngspice keeps every vector in memory.
- Every run has a timeout (`DEFAULT_TIMEOUT`, 30 s; recordings `RECORDING_TIMEOUT_PER_S` per second of audio): `bg_run` + `bg_halt` (D-040). Quick runs stay in the server's process; audio renders run in worker processes (`solum/audio/jobs.py`, D-083).
